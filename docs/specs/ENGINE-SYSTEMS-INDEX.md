# Shader Forge Systems Index

Date: 2026-08-31

`engine_sessiond` remains a loopback-only control plane: it refuses non-loopback bind hosts such as `0.0.0.0` and `::`, keeps session `rootPath` immutable after creation, bounds public JSON bodies while bytes arrive, and owns the revision-safe text-file operation journal. That journal records canonical workspace identity (path plus filesystem `dev`/`ino`), validates the full event sequence and coherent applying/undoing effect shapes on load, appends failure/recovery transitions, and finalizes code-trust artifacts before an operation is `applied` or `undone`. It persists the latest strict bounded validation summary plus up to eight actor-attributed `validated` events for previewed/approved spatial operations. The lease-free HTTP validator now stages the full animation/content/foundation snapshot, verifies private proposed bytes, native-validates and evaluates rest plus at most 64 exact phase/time samples, rejects live-manifest drift, and compare-and-swap records only controlled counts/failures. Restart rejects malformed or mismatched validation provenance; public views never expose private bytes or raw native diagnostics. One semantic dispatcher sends scene and spatial apply/undo through their respective native mutation validators inside the serialized SessionStore lane, with spatial validation directly rechecking current truth and the covering lease without recursively taking the mutation lock. Native spatial child processes have a fixed timeout. All supported mutations, including CLI provenance promote/quarantine and `sf-mcp` spatial attachment changes, share this authority; artifact files use atomic replacement. Cooperative engine clients are covered; hostile out-of-process filesystem swaps at the OS syscall boundary are not an adversarial security guarantee. Non-spatial MCP mutation stays disabled until each operation family persists resource keys and enforces equivalent leases.

Scene/data/runtime now share a strict optional prefab `[component.camera]` perspective source of truth. One root `player_camera` wins over `player_spawn`; its composed transform and authored float32-compatible FOV/clip values drive runtime debug projection, while ordinary scenes retain a 70/0.15/1000 fallback. Parented player cameras fail validation until true parent/local TRS composition exists, and stale quickloads cannot replace the current preferred authority. This does not implement native capture: spatial review still requires deterministic staged cameras, revision binding, frame readback, and immutable packets.

Spatial authoring now has a native schema/query/cook slice, compatible v1 plus strict v2 attachment profiles, strict optional schema-v2 cone-twist limits and diagnostic capsules, a strict optional prefab-only box-collision component in `DataFoundation`, deterministic schema-v2 clip pose sampling, sampled v2 two-bone secondary-hand IK, and exact prefab-bound authored visual-box evidence. Limits/capsules are generation-safe bone snapshot data and cook as deterministic object-or-null fields; prefab collision is typed source snapshot truth independent of render procgeo. Native rest/sample evaluation reports rest-relative cone swing and signed twist plus diagnose-only capsule-axis-to-authored-collision-OBB surface clearance without mutating or clamping the pose. `shader_forge_spatial` emits exact typed aggregate/per-bone joint-limit and aggregate/per-capsule clipping objects; sessiond and Assets validate their stable order, geometry, derived metrics, and aggregate truth fail closed. Missing collision or capsule inputs remain exact typed unavailable evidence rather than silently passing, and tangency is clear with zero violation. Rest/sample separately resolve `item_prefab` through the existing `DataFoundation` prefab `[component.render].procgeo` chain and emit eight deterministic visual-box world corners only for one valid unambiguous box source; the render box never substitutes for collision. Sessiond stages exact animation files, all authored `content/**/*.toml`, and the data-foundation manifest, exposes their sorted revision manifest, and fails closed on source drift or symbolic paths. Assets draws the render-procgeo visual outline and the independent authored collision box/capsules beside the rest/sampled rig while labelling all of it diagnostic schematic evidence rather than a rendered mesh, runtime collision result, or review evidence. Schema-v1 two-hand sampled output remains explicitly pre-IK; v2 exposes physical reach plus separate contact/angular tolerance truth. Semantic operations now include lease-free operation validation and lease-gated apply/undo native revalidation; `sf-mcp` preview/review/apply/undo remain the mutation adapter. The read-only, idempotent `spatial_attachment_read` MCP tool returns exact revision-bound rest or authored sampled evidence without acquiring leases or creating operations. Runtime collision/physics consumption, native capture, immutable review packets, generic bake/runtime consumption, and typed MCP validate/recapture/review adapters remain deferred; see [ENGINE-SPATIAL-AUTHORING-SPEC.md](/mnt/s/Development/AI-Game-Engine/docs/specs/ENGINE-SPATIAL-AUTHORING-SPEC.md).

The shell now consumes the durable operation journal through a global `Activity` bottom-dock tab. `App` owns one sessiond SSE subscription for both Activity and Assets operation notifications. Activity reloads active-workspace list/detail state, while Assets receives an event epoch and authoritatively refetches its active operation with selection/operation race guards. Approval updates actions. Conflict rereads authored bytes, preserves visibly stale candidate evidence, and retains its captured lease only after successful parse and refreshed resource coverage. Reject/apply/undo clear and reread the appropriate evidence and clean up only the connection captured by that event/action, never a newer one; Undo reacquires explicitly after apply. Activity itself shows public provenance and exact bounded text diffs and supports lease-free approve/reject; it deliberately cannot apply/undo, coordinate, or expose internal before/proposed bytes. Public validation summaries now exist in the operation contract, but Activity rendering for them remains deferred.

The shell-native `Code` workspace now owns bounded file browsing, revision-bound Monaco source/diff tabs, current-file search beside `Inspect`, dirty-draft retention, typed revision/state/code-trust conflicts, and explicit Preview/Approve/Reject/Apply/Undo over the same durable operation journal. It never writes through `/api/files/write`; reviewed candidates are bound to exact draft bytes. Request-generation plus session/tab/path/operation guards reject late reads, event refreshes, and actions, while apply/undo baseline refresh uses an expected-draft comparison so a newer edit survives. Active project-session changes keep foreign dirty tabs detached and read-only until their original session returns. Authoritative 409 operation state is adopted only when id, session, and path match. The preserved `web/` editor is an optional compatibility bridge rather than the default workflow.

The React shell now uses one strict v1 browser-persisted layout record: active workspace; per-workspace left/right visibility, tab, and preferred width; and one shared bottom-dock tab, collapsed state, and preferred height. Header toggles, bounded pointer/keyboard separators, and `Reset` operate that record. Layout persistence contains chrome only and falls back to defaults on malformed/unavailable storage. `Playtest` starts with side panes hidden; at narrow width the right pane stays reachable as an overlay drawer instead of consuming the center workspace. `Code` and `World` remain mounted across ordinary workspace navigation. `World` uses draft-preserving `Edit`/`Verify`, explicitly detaches dirty drafts across incompatible project/session changes, and sends all scene/prefab saves through the revision-bound semantic operation lane before Play requests Build + Run. Queued, conflicting, late, or uncertain results preserve drafts; successful apply is reconciled by authoritative operation/file identity. `Playtest` defaults to one plain status/action surface with raw settings, state, logs, and activity under collapsed `Diagnostics`; the top chrome no longer duplicates runtime controls.
